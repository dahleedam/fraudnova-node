> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `@fraudnova/sdk` npm package (official Node.js/TypeScript client, v1.0.0) and wire it into the FraudNova app docs, changelog and examples repo, mirroring the Python SDK that shipped on 2026-11-07.

**Architecture:** A thin `FraudNova` class delegates HTTP to an internal `Transport` (global `fetch`) that decodes the JSON envelope, maps error statuses to typed error classes and applies an opt-in `RetryPolicy`; results are classes with camelCase readonly properties, lenient coercion and `flagged()` helpers. **Tech Stack:** TypeScript 5.9, tsup 8 (ESM + CJS + d.ts), vitest 3, eslint 9 + typescript-eslint 8, prettier 3, Node 18/20/22; Laravel 13 Blade + PHPUnit for Task 7.

**Spec:** `docs/superpowers/specs/2026-11-07-node-sdk-design.md` (this repo). API facts also in the Python spec at `/Users/dahleedam/Herd/fraudnova-python/docs/superpowers/specs/2026-11-06-python-sdk-design.md`.

## Global Constraints

- Node ≥ 18 runtime; **no `dependencies`** in `package.json`; runtime code imports nothing from `node:` (an optional `process.versions.node` read is guarded by `typeof process !== "undefined"`).
- Package name `@fraudnova/sdk`, version `1.0.0`, `"type": "module"`, `publishConfig.access: "public"`, `files: ["dist"]`, `exports` with `import` (`./dist/index.js`) / `require` (`./dist/index.cjs`) / `types` conditions.
- `User-Agent: fraudnova-node/<VERSION> node/<process.versions.node>` on every request; `Authorization: Bearer <key>` on every request except `GET /my-ip`; `Accept: application/json` always; `Content-Type: application/json` on POST.
- `BATCH_MAX = 100`; risk threshold default 75; default flag fields IP `["proxy", "vpn", "tor"]`, email `["disposable"]`, phone `["VOIP", "risky"]`.
- Retry defaults: `maxAttempts: 3`, `concurrencyDelays: [1, 2, 4]`, `rateLimitDelays: [5, 15, 40]`, `honourRetryAfter: true`, `maxRetryAfter: 60` — all **seconds**. Client `timeout` default `30_000` **milliseconds**.
- No file in any of the three repos may contain the upstream provider's name, its four-letter abbreviation, or the two pool-internals phrases (see the leak-guard test, which assembles them from fragments), case-insensitive. Commit messages too.
- The API key never appears in error text, `String(client)` or `util.inspect(client)`.
- Every commit message ends with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Nothing is pushed or published.
- Local commands in the SDK repo: `npm test`, `npm run lint`, `npm run typecheck`, `npm run build` (all four must be clean before every commit). In the app worktree: `php -d memory_limit=512M vendor/bin/phpunit`, `vendor/bin/phpstan analyse --memory-limit=512M`, `vendor/bin/pint --test`.
- Code style: prettier defaults with `printWidth: 100`, double quotes, semicolons, trailing commas `all`; 2-space indent.

## Review Focus

1. A 429 whose body is Cloudflare HTML (no JSON) must still be a `RateLimitError` so retry works; a 401/402/403/422 HTML page must be a plain `ApiError` (never a semantic subclass) — tests in Task 2 (`html 401 is a plain ApiError`, `html 429 is a RateLimitError`).
2. `fraud_score` arriving as `87.5` or `"88"` must still flag at threshold 75; `true` must not be read as `1` by `coerceInt` — test in Task 3 (`coerceInt`).
3. `checkIps` with 250 items must send exactly three POSTs (100/100/50) in order and return 250 items; a rejection on chunk 2 must propagate (not be swallowed) — tests in Task 5 (`checkIps chunks by 100`, `an error on a later chunk propagates`).
4. `Retry-After: 0` must be honoured as a zero-second wait, not treated as absent; a `Retry-After` of 120 with `maxRetryAfter: 60` must stop retrying — tests in Task 2 (`delayFor honours a zero Retry-After`, `delayFor stops when Retry-After exceeds the maximum`).
5. A `fetch` that never resolves must reject with `TransportError` after `timeout` ms, and the timer must be cleared on a normal response so a test process (or a serverless invocation) is not kept alive — tests in Task 4 (`a slow fetch is aborted after the timeout`, `the timeout timer is cleared after a response`).
